# World Model 训练方案

> 目标 2。怎么把游戏交互场景 `(obs, action)` 轨迹训成一个能「给定动作预测世界」的模型。分阶段：先复刻 WHAM 求通路，再升级到可控隐空间，最后接机器人。
> 状态：📐 方案 + 起步配置（WHAM 风格自回归）。**暂不含可跑训练代码**——代码在数据到货后随 Phase 2 落，避免空写一堆跑不起来的脚手架。

---

## 0. 设计原则

1. **先能复现，再求质量**：Phase 2 目标是「在自己数据上把 WHAM 配方跑通、对拍上 `microsoft/wham`」，不是一上来就 SOTA。
2. **先小后大**：200M 档、短上下文、低分辨率（300×180）起步，证明数据有效再投大算力。
3. **控制是终点**：生成漂亮画面只是中间产物，**下游控制成功率**才是对「机器人目标」的真指标。所以架构选型偏向「能拿出可控隐状态」。

## 1. 分阶段

### Phase A — VQ 分词器（visual tokenizer）
- **做什么**：从零训 **VQ-GAN/VQ-VAE**，把 300×180 帧编码成离散 token 网格（对齐 WHAM）。
- **为什么**：自回归世界模型在 token 上预测，分词器质量是上限。
- **完成定义**：重建 PSNR/LPIPS 达标、码本利用率健康、解码无明显块状伪影。
- **备选**：直接复用/微调开源图像分词器省一轮；但自训更贴合游戏交互场景画风。

### Phase B — 自回归世界模型（WHAM 风格，主线起步）
- **架构**：decoder-only transformer，对**交错序列**`[obs_tok…, act_tok, obs_tok…, act_tok, …]` 做下一 token 预测。
- **动作**：把 §data 的定长动作向量量化成 action token，和视觉 token 同序列（WHAM 即此法）。
- **规模**：起步 **~200M**、上下文 ≈ 10 个 `(obs,action)` 对、batch 视显存定。
- **三种推理模式**（同一模型）：world model（动作→画面）、behavior policy（画面→动作）、full（两者）。
- **完成定义**：给定真实动作序列，预测帧与真值的**动作响应一致**（动了该动的、按钮有该有的反应）；可交互 rollout 数秒不崩。

### Phase C — 隐动作 + 可控隐空间（升级到「能控制」）
- **隐动作（LAPA/Genie 思路）**：用 VQ-VAE 从相邻帧学**隐动作**，让**无标注录屏**也能进预训练；再用有标注「真·操作」小集合把隐动作对齐到真实动作。→ 放大可用数据、为跨具身铺路。
- **隐空间动力学（Dreamer/JEPA 思路）**：训练在**隐状态**而非像素上预测的动力学模型（RSSM 或 JEPA predictor）。隐空间预测更高效、更抗像素噪声、**最利于规划/控制**。
- **完成定义**：能在隐空间 rollout 候选动作并区分好坏（为 Phase 4 的 MPC/规划做准备）。

### Phase D — 机器人迁移
→ 见 [`../robotics/robotics_transfer.md`](robotics_transfer.md)。默认走 **V-JEPA 2-AC 式**：冻结视觉编码器 + 动作条件 predictor + MPC，少量真机数据零样本控制。

## 2. 架构选型对照（为什么这样排）

| 选项 | 何时用 | 取舍 |
|------|--------|------|
| 自回归 token（WHAM/Genie） | **Phase B 起步** | 与 LLM 同构、易加动作条件、可对拍 WHAM；推理慢、像素级 |
| 扩散（GameNGen/Oasis/DIAMOND） | 要高画质/实时可玩世界 | 画质好；多步采样贵、动作精确响应难 |
| 隐空间 JEPA / RSSM（V-JEPA/Dreamer） | **Phase C/D 控制核心** | 高效、利于规划；不直接出画面 |
| 隐动作（LAPA） | 贯穿 C/D | 吃无标注数据、跨具身；隐动作需对齐 |

## 3. 评测（世界模型没有单一指标，组合看）

- **动作响应准确度**：给定动作，预测帧是否体现了该动作的后果（可用状态/遥测流当弱标签）。
- **预测一致性时长**：rollout 多久开始漂移/幻觉（Genie 口径）。
- **行为策略质量**：behavior 模式预测的动作 vs 真人动作（top-k / 连续量误差）。
- **★ 下游控制成功率**：把世界模型用于规划/控制后的任务成功率——**对机器人目标最诚实的指标**。
- 对拍：与 `microsoft/wham` 在可比设置下对比，校准我们实现是否正确。

## 4. 算力与成本锚点

- WHAM 实测：1.6B = **98×H100 × 5 天**；200M 档小得多。
- 我们 Phase A/B 起步建议：**单机 8×（A100/H100）量级**先把 200M 跑通；按 token 量/步数估时长。
- 大头其实是**数据管线 + 分词器迭代**，不是单次大训练。先把小循环跑快。
- 云成本：单独跟踪，训练另立预算口径。

## 6. 风险

- 游戏交互场景**动作空间不够丰富** → 世界模型学到的动力学对机器人价值有限。
- **时间对齐错** → 学错因果，且难发现。Phase A 前先做对齐校验。
- **分词器是上限** → 投入别省。
- **过早上规模** → 先用 200M + 数百小时证明通路，再决定要不要烧大算力。
